The software has an interesting paradox in the development world: even the most experienced programmers can not see visible errors in their codes. The phenomenon of "Bug Blindness" documented by Dan Luu is a problem that is based on cognitive psychologist and affects software development processes deeply.

The main causes of this problem are:

- Softwareists work with mental model in mind when writing the code and see mental expectations instead of the actual written code
- Context and expectations, masking reality and missing error Tags
- Code review (code review) may also escape the error of summer by other developers
- Can reveal re-review errors after a fresh perspective and long-in-time
- Automatic tests and static analysis tools play critical role for human eye capture problems

Bug Blindness does not affect only beginner developers. Interestingly, experienced programmers may have more exposure to this problem in complex systems because the mental model is stronger and more likely to leave from reality.

The solution of the problem is to combine technical and human factors. **Etkili code reviw processes** is the most reliable way to capture various perspectives and configured test strategies errors. **Automatic vehicles** if routine problems are detected in advance, it is intensively believed to more critical areas.
